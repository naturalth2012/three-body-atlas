# C 方案：长期文明史普查

## 一、为什么需要这个方案

单个预设的模拟是**一次真实积分**，它的历史长度受物理硬约束：

- 三体世界的动力学时标约 20 个时间单位（r≈3 处的圆轨道周期）；
- 默认积分 T = 8.32，只相当于 0.26 个轨道周期；
- 把 T 拉到 19 时文明代数达到峰值 4 代，之后行星在 T≈28.6 被引力弹弓抛出；
- 行星一旦越过逃逸阈值就被标记 `dead`，此后无论积分到 T=80 还是 T=320，**文明代数不再增加**（实测恒为 1）。

所以"单个预设跑出小说量级的文明史"在物理上不成立。硬要做只有两条路，两条都不能接受：

1. 伪造轨道让行星不逃逸——那就不再是真实积分；
2. 把文明代数和时长脱钩——那是脚本演出，不是模拟。

**C 方案的选择：不修改单次模拟的真实性，另建一个视图，用大量真实积分样本呈现"三体世界的命运分布"。** 单个轨道短命是物理事实；上千个轨道加起来就能看出这个世界的完整可能性。

## 二、方案的三条支柱

### 支柱 1：单次模拟保持原样

`/simulate` 的行为不变。它仍是一次真实积分，仍会因行星逃逸而历史终止。这是诚实的，不修。

唯一改动：`civilizationHistory` 的文案要说明"这段历史到此为止"的原因，让用户理解为什么只有 2 代而不是 200 代。

### 支柱 2：新增文明史普查（`/census`）

对 N 组随机初始条件各做一次真实积分，统计**文明代数**、纪元结构、结局分布。这是 `stabilityScan` 的姊妹功能：后者统计"系统是否稳定"，前者统计"这个行星能孕育几代文明"。

关键设计约束（实测得出）：

- 单次 `simulate` 在 steps=8000 时约 25 ms，60 样本约 1.5 秒，**同步会卡 GUI**；
- 因此必须**分批执行**：路由每次只算一小批（如 12 个样本），客户端连续调用直到完成，中间让出事件循环。

### 支柱 3：长期历史的诚实呈现

普查里最有信息量的不是平均值，而是**分布**：多少比例的初始条件能孕育 0 代、1 代、2 代、3 代以上文明。这直接对应小说的核心命题——三体世界为什么必须逃离。

同时给出"文明代数 vs 恒纪元累计时长"的散点，让用户看到二者正相关，即文明的长度取决于稳定的长度。

## 三、明确不做的事

- **不**修改 `simulate` 的物理行为或默认时长；
- **不**在单次模拟里伪造行星再捕获；
- **不**声称普查结果是"三体文明的真实历史"——它是随机初值下的分布；
- **不**引入 worker（DSH 宿主不保证支持，且增加打包复杂度），改用分批 + 客户端轮询。

## 四、执行步骤

### 步骤 1：统计引擎（`sim.js`）

新增 `civilizationCensus(options)`：

- 复用 `stabilityScan` 的初值构造（随机 scale / 质量比 / 扰动 / 行星半径）；
- 每个样本跑一次 `simulate`，记录：文明代数、恒纪元段数、恒纪元累计时长、乱纪元累计时长、致命灾变数、结局（bound/eject/collapse）、行星是否逃逸；
- 支持 `offset` / `limit` 分批，返回本批结果与是否完成；
- 返回聚合：直方图、均值、中位数、最大值、按结局分组的代数均值、相关系数。

### 步骤 2：路由（`index.js`）

- 新增 `CENSUS_PATH = BASE + '/census'`，注册为 `registerAction`（POST，因为要传 offset/limit）；
- 参数夹取：`samples` 上限、`offset` 上限、`limit` 上限；
- 复用现有 `routeHandler` / `actionHandler` 的跨站防护（自动生效，无需额外代码）。

### 步骤 3：Agent 工具（`index.js`）

在已有的 10 个工具旁新增第 11 个 `three_body_census`，让对话里也能问"三体世界能孕育几代文明"。

### 步骤 4：客户端视图（`client.js`）

在"模拟"页的子标签里新增"文明史普查"：

- 运行按钮 → 循环调用 `/census` 直到 `done`；
- 展示：代数直方图、结局饼图（复用 `tba-legend`）、关键指标卡、散点图（恒纪元时长 vs 代数）；
- 进度提示（"已采样 24/60"）。

### 步骤 5：自检断言（`scripts/selfcheck.mjs`）

- `civilizationCensus` 分批语义：两次调用拼起来等于一次全量；
- 聚合数学：直方图总和 == 样本数；均值 == 逐项均值；
- 确定性：同 seed 两次结果相同；
- 路由存在性与参数夹取；
- 文案不含"真实历史"这类断言。

### 步骤 6：文档

`docs/ARCHITECTURE.md` 增加一节说明普查的口径与局限；README 补一句能力说明。

## 五、验收标准

1. 自检全过（当前 658 项，新增后应更多）；
2. `/census` 分批调用能拼出完整结果，且与一次性全量一致；
3. 客户端视图能跑完一次普查并显示分布；
4. 单次 `/simulate` 行为**未改变**（回归验证）；
5. 跨站防护对 `/census` 同样生效；
6. 文档明确说明这是分布统计，不是单一历史。
