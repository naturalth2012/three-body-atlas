# 英文版策略：判断与取舍

> 记录于 2026-11-22。这是一份**决策记录**，不是执行计划——执行计划见
> [`PLAN-EN.md`](PLAN-EN.md)。

## 问题

插件是否需要英文版？

## 结论

**需要，但只做「英文可用」（A 档），不做「英文完整」。**

理由不是成本，而是**内容性质**：这个插件里约 95% 的文字是文学性叙述
（人物档案、剧情节点、地点技术术语描述），机翻会毁掉它；而唯一真正需要
国际化的部分——那个真跑的三体模拟——只占全部文字的 4.7%。

## 实测依据

### 已经双语的部分

| 层 | 覆盖 |
|---|---|
| UI 外壳（标签、按钮、提示） | ZH 256 键 / EN 256 键，`t()` 用到 205 个，零缺失 |
| 实体名称 | 人物 56/56、术语 37/37、地点 19/19、技术 24/24 |
| 台词英文 | 5/30（其余 25 条为 `verbatim: true` 的原著直引，见下） |

### 仍然只有中文的部分

| 内容 | 中文字数 | 占比 |
|---|---:|---:|
| 人物档案 | 15,625 | 35.3% |
| 剧情节点 | 11,231 | 25.4% |
| 地点/技术/术语描述 | 9,455 | 21.4% |
| 时间线事件 | 5,615 | 12.7% |
| **模拟叙事（旗舰功能）** | **2,057** | **4.7%** |
| 其他 | 229 | 0.5% |
| 合计 | 44,212 | 100% |

已翻译的部分约 5,696 字符——**不到未翻译量的 13%**。

## 为什么不做完整英文版

### 1. 旗舰功能只占 4.7%

那个「真的会跑起来」的三体模拟——包括纪元判定、灾变叙事、四角度解读、
文明代数、文明史普查——全部文字只有 2,057 字。把它英文化，英文用户就能
用到这个插件的全部**功能**，成本极小。

### 2. 文学性文本不能机翻

人物档案（35%）与剧情节点（25%）是叙述文字，涉及原著的语气、伏笔与
人物关系。机翻产出会低于这个插件其余部分的水准，反而不如诚实标注
「原文为中文」。

### 3. 原著台词不该翻

30 条台词里 25 条标了 `verbatim: true`，是原著直引（如「不要回答！不要
回答！不要回答！」）。翻译它们等于制造一份伪原著——既在版权上不妥，也
在诚信上说不通。这 25 条应当保留原文，英文界面显示中文原文 + 现有英文
说明，而不是替换。

### 4. 市场条目已经在承诺英文

`market-entry.yml` 的 `en:` 描述写得相当完整。英文用户装上后看到满屏中文
档案，是**承诺与交付不符**——这比不提供英文更伤。A 档的主要动机之一就是
消除这个落差。

## A 档的确切范围

1. **模拟叙事英文化**：`sim.js` 与 `engine.js` 里所有返回给调用方的叙述文字
   （约 2,057 字），包括预设名/描述、灾变 `kind`/`severity`/`text`、
   四角度解读、文明叙事、普查结论。
2. **工具文案统一英文**：`index.js` 的 34 条工具描述里 10 条含中文，
   统一为英文（给 Agent 读的接口说明不该混语言）。
3. **市场条目修正**：工具数 10 → 11，并如实说明档案为中文原文。
4. **不做**：人物/剧情/地点/技术/术语的描述翻译，25 条原著台词不翻。

## 一个必须解决的技术约束

`severity` 与 `kind` 的取值**既是显示文本，又是逻辑判断依据**：

```js
const lethal = catastrophes.filter((c) => c.severity === '毁灭' || c.severity === '致命')
```

所以不能直接把 `'毁灭'` 改成 `'devastating'`——那会让所有依赖这些字面量的
筛选静默失效。正确做法是拆成**稳定标识 + 显示文本**：逻辑用
`severity: 'devastating'`，显示走 i18n 映射表。这条约束是 A 档最大的
实现风险，也是执行计划里第一件要处理的事。

## 结论一句话

英文用户应当能**用**这个插件（跑模拟、看结论、查实体名），
但**读**完整图鉴仍需要中文——这一点应当明说，而不是假装已经支持英文。
