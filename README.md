# 三体宇宙图鉴

把刘慈欣《三体》三部曲（以及《球状闪电》前史）的**剧情脉络、人物关系、纪元时间线、技术造物、三体游戏关卡、术语名句与改编差异**整理成一套可以在侧边栏里自由探索的图鉴，并内置一个**真的会跑起来的三体引力模拟**。

## 它能做什么

**十六个标签页，从不同角度进入三体宇宙：**

| 标签 | 内容 |
| --- | --- |
| 🧭 概览 | 数据规模、纪元分布、来源层级，一键跳转入口 |
| 📔 导读 | 五条精心编排的阅读路线，每条说明「为什么这样读」，并记录走到第几步 |
| 📖 剧情脉络 | 四部作品（三体 / 黑暗森林 / 死神永生 / 球状闪电）分步主线，每步标注纪元、年份与出场人物 |
| 👤 人物图谱 | 56 位角色的搜索与档案；阵营 / 作品 / 身份三重筛选；档案含生平、关系、地点、技术、名句、议题与事件 |
| 🎭 角色视角 | 选一个角色，把他/她经历的**全部事件与情节按顺序**排成一条线，并标出哪些由他/她主导 |
| 🕸️ 关系与路径 | 力导向交互关系网络：拖动、缩放、聚焦、阵营高亮；另有两人之间最短关系路径查询 |

| ⚖️ 多角度议题 | 8 个议题，每个都有两种以上对立立场与可以继续争论的地方 |

## 剧透分级：读到哪儿，就看到哪儿

三部曲的全部张力都建立在「你还不知道接下来会发生什么」上。插件因此给每条记录标了分级，顶部可以选自己读到第几部：

- 分级来自数据本身（`firstWork`、`works`、`work`），不是另打一套标签，所以不会与目录脱节。术语是唯一没有作品字段的数据集，由 `data/spoiler.js` 显式补齐 37 条。
- 超出进度的记录**不会被删掉**：名字和一句话简介保留，结局、长传记、事件标题被遮蔽，并标明属于哪一部。这样你仍然知道「有这么个东西存在」。
- 遮蔽会穿透子列表。选第一部的读者打开程心，她的 19 个事件、8 个地点、4 项技术全部折叠；而叶文洁的第一部材料（4 个事件、2 个地点）照常显示。关系描述也会遮蔽，因为「从执剑人手中接过开关」本身就是剧透。
- **默认是全部展开**，不挡路。选择会记住；如果浏览器禁用了本地存储，退化为本次会话内有效，页面不会因此报错。
- 面板与 Agent 工具共用同一套判定：工具不传 `maxTier` 时默认不遮蔽，传了才收紧。

## 角色视角：同一件事，不同的重量

选一个角色，把他/她出现的**情节节点与时间线事件**合成一条有序的故事线，并标注三种分量：

- **主导**：情节标题点名了这个角色，说明这件事由他/她推动。
- **被点名**：名字出现在描述里，但不是标题里的行动者。
- **在场**：只是被列入出场人物。

分量的判定来自文本，**不是数组顺序**。这一点很关键：`characters[0]` 常常不是主角——「不要回答」里第一位是 1379 号监听员，真正按下发射键的是叶文洁。

诚实说明：46 个情节里只有 14 个的标题点名了行动者，其余按「被点名／在场」如实降级，不猜测。另有 19 位角色没有任何独立情节节点（魏成、萨伊、秦始皇等），插件会明确标注他们属于配角或背景设定，并给出关系入口，**而不是编造内容**。

## 概念图：思想如何互相推导

术语的 `related` 字段本身就是跨类型的引用（121 条边：48 条指向术语、23 条指向技术、36 条指向人物、14 条指向地点）。把它解析出来就是一张真实的依赖图：

- 从「黑暗森林法则」出发能走到猜疑链、宇宙社会学、罗辑、叶文洁与「咒语（宇宙广播坐标）」。
- 支持 1–3 层展开，节点按类型着色；术语可继续深入，人物／技术／地点点击直接打开档案。
- 名称与 id 都能作为起点（`猜疑链` 与 `chain-of-suspicion` 等价）。
- 同样受剧透分级约束。

## 导读：五条路线，各有理由

五条路线不是书单，而是**读法**：第一次进入三体、宇宙社会学硬核线、人物命运线、改编对照线、哲学向。每条都说明为什么这样排序，每一步展开该部涉及的人物与事件数量，并可标记已读、记录进度。


## 三体模拟：不是示意图

「三体模拟」标签下的每一个点都由**真实的万有引力积分**算出来，不是画出来好看的动画。

**物理内核**
- 速度 Verlet（kick-drift-kick）二阶积分，配合**自适应子步**：最近一对天体的动力学时标决定步长，近距离交会时自动细分，最多 64 步。
- 软化半径 0.01，小到允许真正的近距离交会。实测在 Burrau（3∶4∶5）问题上，这套组合把积分器能量误差压到 0.02%，同时让天体真的能互相靠近（旧方案用 0.045 软化 + 固定步长，靠"糊掉"引力换来 0.06%）。
- **能量与角动量双诊断**：并合辐射掉的能量单独记账，不会伪装成积分误差；角动量守恒独立校验。
- 经典点质量问题（八字舞、毕达哥拉斯）显式标记为不并合——它们本来就没有半径。

**灾变判定**（全部由积分出的坐标推导，不是写死的剧情）
- **三日凌空**：行星落在三颗恒星的三角形内，且最近一颗近到足以烤焦地表。
- **三日同现**：在三角形内但距离仍温和，是可以躲进地下的程度。
- **三日连珠**：三颗恒星近似共线，**且行星也在这条线上**。
- **潮汐撕裂／行星被吞噬**：按罗希极限判定，用物理半径而非绘制半径。
- **飞散／并合**：抛出系统，或真实接触。

**文明的代数**
每个恒纪元窗口是一代文明；被灾变打断的，就是被抹去的那一代。原著的「一百多号文明」由此变成一个可数的数字。没有行星的系统会明确报告「0 代文明」，而不是给出误导性的计数。

**分析与可视化**
- 行星辐射史曲线，底色标出恒纪元／乱纪元。
- 能量守恒曲线，漂移随时间的走势。
- 相位图：位置空间（x, y）与速度空间（vx, vy）并排——周期系统两张都闭合，混沌系统两张都不闭合。
- 灾变记录可点击跳转到对应时刻；文明代数用色条显示每一代是被打断还是熬到乱纪元。
- **四角度解读**：数值可信度、稳定还是混沌、行星的处境、与原著对照，每一条都能对着上面的数字核对。

**参数台**
可改任一天体的 x/y/vx/vy 与积分步数。改任何初值都会重新积分整个系统——这就是初值敏感本身。服务端对每个参数做区间钳制，手改请求也无法要求十亿步积分。

**另外五个子面板**：初值敏感、稳定性普查、黑暗森林、威慑博弈，见「三体模拟」标签内的子页签。

## 和对话打通

插件注册了 10 个工具，与面板共用同一套数据与模拟核心：

- `three_body_search` — 全库检索（人物 / 地点 / 技术 / 术语 / 事件 / 议题 / 作品）
- `three_body_detail` — 任一实体的完整档案，可传 `maxTier` 收紧剧透
- `three_body_journey` — 一个角色的完整故事线，逐节点标注主导 / 被点名 / 在场
- `three_body_concept` — 概念之间的跨类型依赖图，可指定层数
- `three_body_relation` — 两位角色之间的最短关系路径，逐跳标注关系
- `three_body_timeline` — 按纪元 / 作品 / 人物筛选时间线
- `three_body_simulate` — 真跑一次三体积分，或做初值敏感测量、稳定性普查、黑暗森林推演、威慑博弈
- `three_body_theme` — 读某个议题的两方立场与开放讨论
- `three_body_game` — 按顺序走一遍三体游戏关卡
- `three_body_ask` — 自由提问

在对话里直接问「罗辑和庄颜是什么关系」「水滴是什么」「为什么三体问题不可解」「黑暗森林法则是什么」「程心经历了什么」「猜疑链怎么推出黑暗森林」即可。

## 已知限制

诚实说明，避免误解：

- **数据为人工整理，未与原著逐行核对。** 细节请以刘慈欣原著与官方作品为准。
- **角色视角的「主导」判定依赖标题是否点名。** 46 个情节里 14 个可以这样判定，其余按「被点名／在场」降级，不猜测。19 位角色没有独立情节节点，插件如实标注为配角而非编造内容。
- **剧情节点没有分支选择。** 数据里没有「如果当初……」的可选决策点，因此没有做「选择改变结局」的交互——那需要手写新内容，不属于现有数据的推导范围。
- **界面外观未在浏览器中实测。** 本项目无浏览器控制能力，暗色主题对比度、窄屏布局、动画帧率未经视觉验证；已通过静态渲染探针（108 次组件渲染、0 错误）与静态检查覆盖结构正确性。
- **剧透分级是阅读辅助，不是安全边界。** 默认全展开；它防止的是无意间读到结局，不是刻意检索。

## 来源标注

每条记录都带来源层级：

- **原著** — 刘慈欣《三体》《黑暗森林》《死神永生》，以及《球状闪电》
- **腾讯剧集** — 2023 年腾讯版《三体》
- **Netflix 改编** — 2024 年《3 Body Problem》，人物与线索被重排
- **动画改编** — 《我的三体》系列
- **非官方同人** — 《三体X：观想之宙》，只作对照提及，并不属于原著

「原著 vs 改编」页逐条说明差异。数据集为人工整理，未做在线逐条核对；细节请以原著与官方作品为准。

## 开发

```bash
node scripts/selfcheck.mjs   # 数据完整性、引擎行为、剧透分级、模拟、路由与清单（656 项）
node scripts/probe.mjs       # 无浏览器渲染全部 16 个标签页、四类抽屉与分级遮蔽分支，捕获元素树错误
```

数据结构的维护者参考见 [docs/SCHEMA.md](docs/SCHEMA.md)。
